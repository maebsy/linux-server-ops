## ⑩ 웹서버 전환 시 추가 지표 — 응답시간(latency) (#17) · 같은 서버에 nginx(Ubuntu 22.04 패키지)를 띄워 측정
### 바깥에서 본 응답시간 — curl 20회, 연결/첫 바이트/전체 시간 중 전체(total)의 p50·p95·max
$ for i in $(seq 20); do curl -o /dev/null -s -w '%{http_code} %{time_connect} %{time_starttransfer} %{time_total}\n' http://127.0.0.1/; done > /tmp/lat.txt; head -n 3 /tmp/lat.txt; echo ...; awk '{print $4*1000}' /tmp/lat.txt | sort -n | awk '{a[NR]=$1} END {printf "n=%d p50=%.2fms p95=%.2fms max=%.2fms\n", NR, a[int(NR*0.5)], a[int(NR*0.95)], a[NR]}'; awk '$1 != 200' /tmp/lat.txt | wc -l | xargs echo '200 이 아닌 응답 수:'
200 0.000172 0.000595 0.000649
200 0.000171 0.000528 0.000578
200 0.000167 0.000575 0.000669
...
n=20 p50=0.65ms p95=0.72ms max=0.82ms
200 이 아닌 응답 수: 0
(exit code: 0)

### 서버 안에서 본 처리시간 — access log 에 $request_time 을 남기는 형식 추가 (기존 access.log 는 그대로)
$ install -m 0644 /root/timing.conf /etc/nginx/conf.d/timing.conf; cat /etc/nginx/conf.d/timing.conf; nginx -t 2>&1 && systemctl reload nginx
# 응답시간 기록용 형식 (기존 access.log 는 그대로 두고 timing.log 를 하나 더 남긴다)
log_format timing '$remote_addr [$time_local] "$request" $status rt=$request_time';
access_log /var/log/nginx/timing.log timing;
nginx: the configuration file /etc/nginx/nginx.conf syntax is ok
nginx: configuration file /etc/nginx/nginx.conf test is successful
(exit code: 0)

$ for i in $(seq 20); do curl -o /dev/null -s http://127.0.0.1/; done; tail -n 2 /var/log/nginx/timing.log

### 임계값 판정 예 — 최근 100건 p95 가 LATENCY_WARN_MS(예 200ms)를 넘으면 WARNING (monitor.sh 의 CPU/MEM 경고와 같은 '경고만' 등급)
$ LATENCY_WARN_MS=200; p95=$(tail -n 100 /var/log/nginx/timing.log | grep -o 'rt=[0-9.]*' | cut -d= -f2 | sort -n | awk '{a[NR]=$1} END {printf "%.1f", a[int(NR*0.95)]*1000}'); echo "p95=${p95}ms"; awk -v p="$p95" -v t=$LATENCY_WARN_MS 'BEGIN { if (p > t) print "[WARNING] latency p95 " p "ms > " t "ms"; else print "[OK] latency p95 " p "ms <= " t "ms" }'
p95=0.0ms
[OK] latency p95 0.0ms <= 200ms
(exit code: 0)

→ 정적 페이지라 nginx 내부 처리시간은 0.000초(ms 단위 해상도). 앱 서버 앞의 리버스 프록시라면 $upstream_response_time 을 같은 방식으로 본다.
