# 방법: 같은 Ubuntu 22.04 이미지로 띄운 별도 컨테이너 fw-server 에서 ufw 를 제거하고 firewalld 를 설치한 뒤 스크립트 실행. 바깥 확인은 같은 네트워크의 ops-laptop

## ⑤ 바깥(ops-laptop)에서 접속 확인 — 서버에는 20022(sshd) · 15034(가짜 앱) · 8080(http.server) 가 모두 LISTEN 중
$ (fw-server) ss -Hltn | grep -E ":(22|20022|15034|8080)\b"
LISTEN 1      5            0.0.0.0:15034 0.0.0.0:*
LISTEN 0      5            0.0.0.0:8080  0.0.0.0:*
LISTEN 0      128          0.0.0.0:20022 0.0.0.0:*
LISTEN 0      128             [::]:20022    [::]:*

$ (ops-laptop) for p in 22 20022 15034 8080; do timeout 3 bash -c "</dev/tcp/fw-server/$p" && echo "$p open"; done
22 실패: No route to host
20022 open
15034 open
8080 실패: No route to host

→ 허용한 20022 · 15034 만 열립니다. 8080 은 서버에서 LISTEN 중인데도 "No route to host" — firewalld 기본 zone(public)은 허용 안 된 패킷을 ICMP host-prohibited 로 거부(REJECT)합니다(UFW 기본은 DROP 이라 응답 없이 timeout). 22 도 허용 목록에 없어 같은 방식으로 거부됩니다(sshd 도 이제 20022 만 듣습니다).
